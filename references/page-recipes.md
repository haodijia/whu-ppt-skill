# 页型与完整度

先看 `examples.md` 对应预览，再选构图。背景、发现问题、从观察到设计和实验取舍的具体迁移步骤见 [构图说明](composition.md)。完整度由内容关系判断，不能用模板对象数量判断。

| 页型 | 应当同页建立的关系 | 常见内容缺项 |
|---|---|---|
| 背景与需求 | 真实对象或应用场景、任务要求、现有限制及研究问题 | 只有一句“意义重大”和装饰照片 |
| 现状比较 | 统一比较维度、代表方法及依据、机制差异和未解决处；需要时放代表图 | 四张卡片只写方法名与优缺点标签 |
| 问题观察 | 可观察的案例/曲线、具体差异、原因和设计依据 | 只有问题清单，没有现象证据 |
| 输入与定义 | 一个具体输入、表示或计算、输出形式、符号与条件 | 点线面、图像、文本都被替换成写着名字的方框 |
| 架构 | 总图的输入、分支、连接、输出；关键模块局部细节与对应说明 | 只有三个流程框，并用动画掩盖机制缺失 |
| 内部计算 | 总体定位、放大模块、必要公式与符号、信息怎样变化 | 只说“增强特征”“融合信息” |
| 训练与推理 | 监督信号、优化对象、损失、训练/部署差异；已知关键参数 | 只列模型名称，省略新增对象如何获得结果 |
| 数据与协议 | 来源、规模、样本/分布、划分、指标定义、公平比较条件 | 只有数据集名称，结果页没有可解释的比较基准 |
| 主结果 | 相关完整对照、指标与误差、视觉证据或任务分组、结论及范围 | 两个大数字、一张过小原图、空泛“明显提升” |
| 消融与机制分析 | 控制变量、基线和变体、对应结果、作用与代价 | 把主结果当消融，或从同时改变多项的结果推断单一原因 |
| 定性案例 | 原始输入、结果、局部对照、图例和具体观察 | 图片虽多，但不说明看哪里、差异意味着什么 |
| 总结与局限 | 每项结论回指机制和证据，局限指向适用条件 | 重复摘要或泛泛说“提升效率、增强鲁棒性” |

## 构图选择

- 左侧完整场景与约束，中间纵向结果图与能力分组，右侧应用，底部归纳：参照第 3 页。
- 左侧大幅证据，用四色定位框与引线接到右侧两行解释，底部归纳共同问题：参照第 4 页。
- 上部整体与局部观察接困难，下部补充案例和机制图分别接两条设计思路：参照第 5 页。
- 多行证据分别接观察与取舍，保持控制变量和结论边界：参照第 6 页。
- 图与说明各占一侧：适合公式、模块机制和定性解释；比例按图形细节调整，不固定五五开。
- 总图跨上半页，局部放大与说明在下方：适合复杂网络，局部与总图用对应标记连接。
- 多图对照上方，分析与条件在下方：适合数据规模、参数和机制分析。
- 结果图组与表格并置：保留对照对象的一致性，图表表达互补信息。
- 信息较多的表格可以占据主区域，解释放邻近位置；无需另造几张稀疏“结论页”。

使用留白建立层次，但不能因为“大图＋一句话”易排版而删去必要解释。参照页的彩色说明框、局部引线和结论条应保留相应作用；不能为了统一简洁风格将它们全部删掉。背景、方法、实验采用各自的视觉结构。

## 公开示例的迁移

`assets/whu-template.pptx` 中，SAM 示例包含场景背景、案例定位、从观察到设计、实验取舍；ViT 示例展示分块尺寸计算、总图和局部机制、比较表与任务分组、机制分析。两组是独立页型案例，不是同一篇论文的连续汇报。

迁移到用户材料时，保留这些解释层级，重新选取源图和相关数据。不要复用示例的事实、结论或图像来填补用户论文的空缺。
